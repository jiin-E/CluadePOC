## 2. 코드 리뷰 분류

`server/` 를 정확성 · 보안 관점으로 리뷰했다(코드만 읽음). SQL 인젝션은 없고, 409 규칙은 조건부 UPDATE 로 맞게 구현돼 있다.

분류 기준: POC 성공 기준과 데모에 영향을 주면 **즉시 수정**, 제품으로 만들 때 필요하면 **보고서 기록**, 그 밖은 **제외**.

분류 이유

- 1번: SPEC (b) 「대여일 + 14일」을 직접 어기고, 오전 데모에서 바로 드러난다.
- 2번: 화면은 늘 올바른 JSON 을 보내므로 데모에는 영향이 없다. 하지만 운영에서는 경로 노출과 오류 응답 형식 불일치가 문제가 된다.
- 4번: 데모는 `npm run dev -w server` 로 띄워 영향이 없다. 운영에서는 DB 경로를 고정해야 한다.
- 6번: 성공 기준 (a)~(d) 밖의 오류 경로라 POC 판정에는 필요 없지만, 제품에서는 회귀 테스트로 있어야 한다.
- 3 · 5번: 동작에 실제 피해가 없거나, 지금 코드에서는 안전하다.

## 3. 수정 내용 (1번)

- `server/app.js`: 반납 예정일을 서버 시간대의 날짜로 계산해 `YYYY-MM-DD` 로 저장한다.
- `server/test/books.test.js`: 시간대를 `Asia/Seoul` 로 고정하고, 대여 시각을 KST 2026-10-31 08:00 으로 고정해 예정일 `2026-11-14` 를 확인한다. 수정 전 코드에서는 `2026-11-13` 이 나와 실패하는 것을 확인했다.

## 4. 판정

**조건부 적합**

- API 기준으로 성공 기준 (a)~(d) 의 자동 테스트가 모두 통과했고, 즉시 수정 항목(1번)도 고쳤다.
- 다만 SPEC 의 판정 방법은 「자동 테스트 + 화면」 이고, 화면은 아직 브라우저에서 확인하지 않았다. 화면에서 (a)~(d) 를 직접 눌러 확인하면 적합으로 바꾼다.
- 제품으로 넘어가려면 2절의 보고서 기록 항목(2 · 4 · 6번)을 먼저 처리해야 한다.
