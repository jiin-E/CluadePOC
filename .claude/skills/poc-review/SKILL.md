# POC 코드 리뷰

리뷰 대상: `$ARGUMENTS` (비어 있으면 `server/`)

## 규칙

- 코드만 읽는다. 서버를 띄우거나 `npm test` 를 실행하지 않는다.
- 사용자가 따로 요청하기 전에는 파일을 고치지 않는다.
- 답은 한국어로 쓴다.

## 순서

1. **리뷰 위임**: Agent 도구로 `code-reviewer` 에이전트를 호출한다. 프롬프트에 리뷰 대상 경로를 넣고, 코드만 읽어서 리뷰하라고 적는다.
   `code-reviewer` 를 쓸 수 없으면 `general-purpose` 에이전트에 `.claude/agents/code-reviewer.md` 를 읽고 그 지침대로 리뷰하라고 맡긴다.
2. **검증**: 받은 결과 중 심각도가 「높음」 · 「중간」 인 항목은 해당 파일:줄을 직접 Read 로 열어 주장이 맞는지 확인한다. 틀린 항목은 빼고, 확인하지 못한 항목은 「확인 필요」 로 표시한다.
3. **분류**: 각 항목을 다음 기준으로 나눈다.
   - **즉시 수정**: `docs/SPEC.md` 의 성공 기준 (a)~(d) 또는 데모에 영향을 준다
   - **보고서 기록**: 데모에는 영향이 없지만 제품으로 만들 때 필요하다
   - **제외**: 그 밖(실제 피해가 없거나 POC 범위 밖)
4. **보고**: 아래 형식으로 보여 준다.

## 보고 형식

| # | 파일:줄 | 심각도 | 관점 | 문제 | 이유(실패 장면) | 분류 |
|---|---|---|---|---|---|---|

- 심각도 순서(높음 → 중간 → 낮음)로 정렬한다.
- 표 아래에 「문제 아님으로 확인한 것」을 1~3줄로 적는다.
- 마지막에 즉시 수정 항목 중 먼저 고칠 1~2개를 추천하고, 고칠지 사용자에게 묻는다.
- 사용자가 결과를 문서로 남기라고 하면 `docs/poc-result.md` 의 리뷰 분류 표를 갱신한다.
