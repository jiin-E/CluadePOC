# SPEC — 사내 도서 대여 POC

## 목표

팀 서가의 책 목록과 대여 상태를 웹 화면 하나에서 보고, 이름만 입력해 빌리고 반납할 수 있게 한다.
하루 안에 「목록 → 대여 → 이미 빌린 책 거부 → 반납」 흐름이 동작하는지 확인한다.

## 성공 기준

판정 방법: API 는 자동 테스트로 상태 코드와 응답을 확인하고, 화면은 브라우저에서 직접 눌러 확인한다.
(a)~(d) 가 모두 통과해야 POC 성공이다. 하나라도 실패하면 POC 실패다.

| 번호 | 기준 | 통과 조건 | 판정 |
|---|---|---|---|
| (a) | 목록 | `GET /api/books` 가 200 과 샘플 책 5권을 돌려준다. 각 책에 제목 · 대여 상태 · 대여자 이름 · 반납 예정일이 들어 있다. 화면에 5권이 상태와 함께 보인다 | 자동 테스트 + 화면 |
| (b) | 대여 | 대여 가능한 책에 이름을 넣어 대여하면 200 이 오고, 그 책의 borrower 에 이름, borrowed_at 에 대여 시각, due_date 에 반납 예정일(대여일 + 14일)이 채워진다. 이름이 비어 있으면 400 으로 거부한다. 화면에서 대여하면 목록에 바로 반영된다 | 자동 테스트 + 화면 |
| (c) | 중복 대여 거부 | 대여 중인 책을 다시 대여하면 409 와 「이미 대여 중인 책입니다.」 로 거부한다. 그 책의 대여자와 반납 예정일은 바뀌지 않는다. 화면에 거부 메시지가 보인다 | 자동 테스트 + 화면 |
| (d) | 반납 | 대여 중인 책을 반납하면 200 이 오고, 그 책의 borrower · borrowed_at · due_date 가 비워져 「대여 가능」 이 된다. 반납한 책은 다시 대여할 수 있다. 화면에서 반납하면 목록에 바로 반영된다 | 자동 테스트 + 화면 |

## 만들 것

- **스택:** Node.js 24 · Express 5 · better-sqlite3 · React + Vite
- **폴더:** `server/` 는 API, `client/` 는 화면, `docs/` 는 문서
- **표 1개:** `books`(id · title · author · borrower · borrowed_at · due_date). borrower 가 비어 있으면 대여 가능이다
- **샘플 데이터:** 책 5권. 서버를 처음 시작할 때 넣는다
- **API 3개**

  | 메서드 · 경로 | 하는 일 | 응답 |
  |---|---|---|
  | `GET /api/books` | 책 목록과 대여 상태 · 대여자 · 반납 예정일 | 200 |
  | `POST /api/books/:id/borrow` | 본문 `{ "name": "..." }` 로 대여 | 200 · 빈 이름 400 · 대여 중 409 · 없는 책 404 |
  | `POST /api/books/:id/return` | 반납(누구나 할 수 있다) | 200 · 대여 중이 아님 409 · 없는 책 404 |

- **핵심 규칙 1개:** 대여 중인 책은 다시 빌릴 수 없다. 어기면 409 로 거부한다
- **화면 1개:** 책 목록 표(제목 · 저자 · 상태 · 대여자 · 반납 예정일), 이름 입력칸, 책마다 대여 · 반납 버튼, 오류 메시지 표시
- **자동 테스트:** 성공 기준 (a)~(d) 의 API 부분을 확인하는 테스트

자세한 설계는 [design.md](design.md) 에 있다.

## 만들지 않을 것

- 로그인 · 회원 관리(이름만 입력한다)
- 반납자 확인(빌린 사람이 아니어도 반납할 수 있다)
- 대여 이력 저장 · 화면(현재 대여자만 남긴다)
- 연체 처리(반납 예정일은 보여 주기만 하고, 지나도 막거나 표시하지 않는다)
- 책 추가 · 수정 · 삭제
- 검색 · 예약 · 알림
- 배포 · 결제 · 외부 API 연동
